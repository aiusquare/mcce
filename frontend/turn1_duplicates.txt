Q3 did show something useful: **the `courses` table has duplicate rows for the same code.**

| Code | Rows in `courses` |
|---|---|
| BIO111 | 2 |
| ENG111 | 3 |
| ENG131 | 3 |

Each row has a different `id`. This matters because registrations can sit on one `course_id` while result batches use another. That would explain scores that look "unregistered", and it ties back to the duplication you suspected earlier. The reconciliation and broadsheet code try to merge duplicates by code. That merge is a workaround, not a fix.

Please run the block below as a single execution. It needs no variables.

```sql
-- A. All duplicate course codes: one row per course id, with usage across ALL sessions
SELECT c.code, c.id AS course_id, c.title, c.credit_units, c.programme_id, c.created_at,
  (SELECT COUNT(*) FROM course_registration_items cri WHERE cri.course_id = c.id) AS reg_items,
  (SELECT COUNT(*) FROM result_batches rb WHERE rb.course_id = c.id) AS batches,
  (SELECT COUNT(*) FROM result_attempts ra JOIN result_batches rb ON rb.id = ra.batch_id
     WHERE rb.course_id = c.id AND ra.total_score IS NOT NULL) AS scored_attempts
FROM courses c
WHERE c.code IN (SELECT code FROM courses GROUP BY code HAVING COUNT(*) > 1)
ORDER BY c.code, c.created_at;

-- B. Session ids (so we know what to filter on)
SELECT id, name FROM academic_sessions;

-- C. Programme id
SELECT id, name FROM programmes WHERE name LIKE '%Educational Administration%';
```

**A** is the key query. It will show which duplicate `course_id` holds the registrations and which holds the scores. If they differ for ENG111, ENG131 and BIO111, that is the root cause of the "unregistered score" report, and the fix is to merge the duplicate course rows.
